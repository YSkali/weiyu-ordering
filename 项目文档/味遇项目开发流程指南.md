## 阶段一：数据库设计（第 1-2 天）

### 做什么

设计整个系统的数据模型，写 SQL 建表脚本。

### 思路

先想清楚「系统里有哪些实体，它们之间是什么关系」：

```
用户(User) ──┬── 下单 ──→ 订单(Order) ──→ 订单项(OrderItem) ──→ 菜品(Dish)
             │                                                        │
             ├── 积分变动 ──→ 积分流水(PointsFlow)                    │
             │                                                        │
             ├── 评论 ──→ 评论(Comment) ←──── 关联 ──────────────────┘
             │
             └── 兑换 ──→ 兑换请求(ExchangeRequest) ──→ 兑换奖励(ExchangeReward)

菜品(Dish) ──→ 分类(Category)

管理员(Admin User) ── 口令(GroupCode) ──→ 顾客(Customer User)
```

### 建表顺序

```sql
-- 1. 先建没有外键依赖的表
CREATE TABLE user (...);
CREATE TABLE category (...);

-- 2. 再建依赖上面的表
CREATE TABLE dish (...);
CREATE TABLE points_flow (...);
CREATE TABLE exchange_reward (...);

-- 3. 再建依赖更多的表
CREATE TABLE dish_visible_users (...);
CREATE TABLE comment (...);           -- 自引用（parentId）
CREATE TABLE exchange_request (...);
CREATE TABLE `order` (...);
CREATE TABLE order_item (...);
```

### 关键设计决策

1. 用户表统一存管理员和顾客，用 `role` 字段区分
2. 订单 ID 用 UUID 字符串，不暴露业务量
3. 积分变动用乐观锁（`version` 字段），防止并发扣积分出错
4. 菜品软删除（`isDeleted` 字段），不真删数据
5. 口令机制：管理员有 `groupCode`，顾客注册时输入口令加入对应组

## 阶段二：后端项目搭建（第 3-5 天）

### 做什么

用 NestJS 搭建后端骨架，配置好数据库连接、JWT 认证、全局拦截器。

### 步骤

#### 2.1 初始化项目

```bash
nest new server
cd server
npm install @nestjs/typeorm typeorm mysql2
npm install @nestjs/jwt @nestjs/passport passport passport-jwt
npm install bcrypt class-validator class-transformer
npm install multer uuid axios
```

#### 2.2 搭建全局基础设施

先搭好「骨架」再写业务：

```
server/src/common/
  guards/           -- JWT 认证守卫、角色守卫
  decorators/       -- @Public()、@Roles()、@CurrentUser()
  interceptors/     -- 统一响应格式 { code, message, data }
  filters/          -- 统一错误处理
  dto/              -- 通用分页参数
strategies/
  jwt.strategy.ts   -- JWT 策略（从 token 提取用户）
```

#### 2.3 编写实体

按数据库设计，用 TypeORM 装饰器定义实体类。

**注意**：本项目读操作全部用 raw SQL，只用实体做写操作（save/update）。原因是 TypeORM 的列映射（`name: 'cate_id'` vs 属性名 `cateId`）在查询时容易出错。

## 阶段三：认证模块（第 5-6 天）

### 做什么

实现登录、注册、JWT 签发和验证。这是所有业务模块的基础。

### 核心逻辑

```
用户提交 account + password + groupCode
    ↓
查找用户是否存在？
    ├── 存在 → bcrypt 比对密码 → 签发 JWT
    └── 不存在 + 有 groupCode → 注册为顾客 → 签发 JWT
    └── 不存在 + 无 groupCode → 报错
```

### 接口清单

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /v1/auth/account-login | 账号密码登录/注册 |
| GET | /v1/auth/me | 获取当前用户信息 |

## 阶段四：菜品模块（第 7-9 天）

### 做什么

实现菜品的 CRUD、分类管理、活动价格计算。

### 核心逻辑

**活动价格计算**：如果当前时间在活动时间内，返回活动价；否则返回原价。

**分页查询**：支持分类筛选 + 关键词搜索 + 分页，使用 raw SQL 避免 TypeORM 映射问题。

## 阶段五：订单模块（第 10-13 天）

### 做什么

实现下单、接单、制作、完成、确认的完整订单流程。这是最复杂的模块。

### 状态机

```
created（已下单，积分未扣）
  ↓ 管理员接单
preparing（制作中，积分已扣）
  ↓ 管理员完成所有菜品
completed（已完成，管理员获得积分）
  ↓ 顾客确认
confirmed（已确认，终态）

created → cancelled（取消，终态）
```

### 关键：积分扣减的事务安全

必须用数据库事务 + 悲观锁（`SELECT ... FOR UPDATE`）：

```typescript
async acceptOrder(orderId: number, adminUid: number) {
  const queryRunner = this.dataSource.createQueryRunner();
  await queryRunner.connect();
  await queryRunner.startTransaction();
  try {
    // 1. 悲观锁查用户
    const user = await queryRunner.manager
      .createQueryBuilder(User, 'user')
      .setLock('pessimistic_write')
      .where('user.uid = :uid', { uid: order.uid })
      .getOne();
    // 2. 检查积分 → 3. 扣积分 → 4. 记流水 → 5. 更新订单状态
    await queryRunner.commitTransaction();
  } catch (e) {
    await queryRunner.rollbackTransaction();
    throw e;
  } finally {
    await queryRunner.release();
  }
}
```

## 阶段七：兑换模块（第 17-19 天）

### 做什么

实现积分奖励的创建、审核、兑换流程。

### 流程

```
顾客创建奖励提案（待审核）
  ↓ 管理员审核
  ├── 通过 → 管理员可以兑换
  └── 拒绝 → 顾客可修改后重新提交

顾客兑换已通过的奖励 → 创建兑换请求
  ↓ 管理员审核
  ├── 通过 → 扣顾客积分，库存 -1
  └── 拒绝
```

## 阶段八：评论模块（第 20-21 天）

### 做什么

### 关键设计：分组隔离

```typescript
// 顾客：只能看到自己组的评论 + 自己管理员的评论
if (currentUser.role === 'customer') {
  qb.andWhere('(user.adminUid = :adminUid OR comment.uid = :adminUid)',
    { adminUid: currentUser.adminUid });
}
// 管理员：只能看到自己组顾客的评论 + 自己的评论
if (currentUser.role === 'admin') {
  qb.andWhere('(user.adminUid = :adminUid OR comment.uid = :adminUid)',
    { adminUid: currentUser.uid });
}
```

### 核心原则

1. **先后端再前端**：先把 API 调通，再写页面
2. **先骨架再细节**：先搭好认证、响应格式、错误处理，再写业务
3. **先核心再扩展**：先做登录→菜品→下单→积分，再做评论、兑换
4. **先功能再美化**：页面能用后再加动画、视觉效果
5. **先单人再多人**：先让一个管理员跑通，再做分组隔离

## 附录：开发踩坑记录

以下是开发过程中遇到的实际问题和解决方案，供复刻时参考。

### 后端

**Express.Multer.File 类型找不到**
- 原因：没有安装 `@types/multer`
- 解决：`npm install @types/multer --save-dev`，或直接用 `any` 类型

**TypeORM 列映射冲突**
- 原因：`name: 'cate_id'`（snake_case）和属性名 `cateId`（camelCase）在查询时映射失败
- 解决：读操作全部改用 raw SQL，写操作继续用实体

**NestJS ValidationPipe 拒绝未知参数**
- 原因：`forbidNonWhitelisted: true` 配置下，前端传了 `cate_id` 但 DTO 里没有定义
- 解决：在 `PaginationDto` 中添加 `cate_id` 可选字段

**synchronize: true 创建重复列**
- 原因：TypeORM 实体属性名和数据库列名不一致时，synchronize 会创建新列
- 解决：设置 `synchronize: false, dropSchema: false`，手动管理表结构

**version 字段没有默认值**
- 原因：插入种子数据时没有给 `version` 赋值
- 解决：INSERT 语句中加 `version: 1`

### 前端

**uni.chooseAvatar 不可用**
- 原因：这是微信小程序特殊 API，必须通过 `<button open-type="chooseAvatar">` 触发
- 解决：改用 `uni.chooseImage`

**菜品搜索功能失效**
- 原因：搜索按钮调用 `fetchDishes(true)` 但没有将 keyword 传给 store
- 解决：先调用 `setKeyword(kw)` 再调用 `fetchDishes(true)`

**评论 parentId 查询条件无效**
- 原因：`parentId: undefined` 在 TypeORM 中会被忽略
- 解决：使用 `IsNull()` 操作符

**兑换奖品分页总数计算错误**
- 原因：用 `list.length` 作为总数，但 list 受 skip/take 限制
- 解决：改用 `findAndCount()` 方法

**下拉刷新圈一直转**
- 原因：`defineExpose({ onPullDownRefresh })` 在 uni-app Vue 3 `<script setup>` 中不生效
- 解决：改用 `import { onPullDownRefresh } from '@dcloudio/uni-app'`

### 交互设计

**管理员端"兑换审核"入口重复** → 删除"我的"页面中的重复入口

**管理员"发放积分"入口不合理** → 移到"用户管理"页面中，点击具体用户后弹出对话框

**客户端"积分明细"页面打不开** → 删除，底部积分卡片已覆盖此功能
