# 味遇点餐系统 — 业务流程

## 一、角色

| 角色 | 说明 | 谁能当 |
|------|------|--------|
| 管理员 | 管理菜品、接单、管积分、审核兑换 | 用 `admin1`~`admin5` 登录，或注册时设置 `role=admin` |
| 顾客 | 下单、签到、兑换奖励 | 用账号+口令登录，口令就是管理员设的 `group_code` |

---

## 二、订单流程（核心）

```
顾客下单                    管理员接单              制作完成              顾客确认
─────────→  ─────────→  ─────────→  ─────────→
 created        preparing       completed       confirmed
    │                              ↑
    └──── cancelled（任一阶段可取消）─┘
```

### 状态流转详解

| 当前状态 | 可变为 | 触发条件 |
|---------|--------|---------|
| `created` | `preparing` | 管理员点"接单"，同时**扣除顾客积分** |
| `created` | `cancelled` | 管理员拒绝 / 顾客取消 |
| `preparing` | `completed` | 所有菜品制作完成（自动） |
| `completed` | `confirmed` | 顾客确认收到 |

### 积分变动节点

- **接单时**（created → preparing）：扣顾客积分，积分暂存系统
- **完成时**（preparing → completed）：管理员获得积分（100% 订单金额）

---

## 三、积分来源

| 来源 | 说明 |
|------|------|
| 管理员充值 | 管理员在后台直接加减积分 |
| 每日签到 | 每天 +10 积分，限 1 次/天 |
| 订单完成奖励 | 管理员完成订单后获得订单金额 100% 的积分 |

---

## 四、兑换流程

### 顾客发起兑换

```
顾客创建奖励申请 → 管理员审核 → 顾客提交兑换 → 管理员审批 → 完成
      (pending)         (approved)                    (扣积分)
```

### 状态说明

| 奖励状态 | 值 | 含义 |
|---------|---|------|
| 待审核 | 0 | 顾客创建，等管理员审批 |
| 已通过 | 1 | 管理员同意，可兑换 |
| 已拒绝 | 2 | 管理员拒绝 |
| 已兑换 | 3 | 已被人兑换过 |

---

## 五、菜品可见性

| visibility | 含义 |
|-----------|------|
| 0 | 所有人可见（默认） |
| 1 | 仅白名单用户可见（在 `dish_visible_users` 表配置） |

## 六、API 接口一览

### 认证 `/v1/auth`

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/login` | 微信登录（需 AppID） |
| POST | `/account-login` | 账号密码登录（顾客需口令） |
| GET | `/me` | 当前用户信息 |

### 菜品 `/v1/dishes`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 菜品列表 |
| GET | `/categories` | 分类列表 |
| GET | `/<id>` | 菜品详情 |

### 订单 `/v1/orders`

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/` | 创建订单 |
| GET | `/` | 我的订单列表 |
| GET | `/<id>` | 订单详情 |
| POST | `/<id>/confirm` | 顾客确认收货 |

### 管理员订单 `/v1/admin/orders`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 本组所有订单 |
| GET | `/<id>` | 订单详情 |
| PUT | `/<id>/status` | 修改订单状态 |
| PUT | `/<id>/items/<itemId>/status` | 修改菜品制作状态 |

### 兑换 `/v1/exchange`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/rewards` | 奖励列表 |
| POST | `/rewards` | 顾客创建奖励申请 |
| POST | `/requests` | 提交兑换申请 |
| GET | `/requests` | 我的兑换申请 |

### 管理员兑换 `/v1/admin/exchange`

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/rewards/<id>/approve` | 通过奖励 |
| POST | `/rewards/<id>/reject` | 拒绝奖励 |
| POST | `/rewards/<id>/claim` | 管理员兑换（扣自己积分） |
| PUT | `/requests/<id>` | 审核兑换申请 |

### 用户 `/v1/users`

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/sign-in` | 每日签到 |
| GET | `/points/flow` | 积分流水 |
| PUT | `/profile` | 修改昵称/头像 |
| PUT | `/account` | 修改账号 |
| PUT | `/password` | 修改密码 |
| POST | `/group-code` | 管理员设置口令 |

### 管理员用户 `/v1/admin/users`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 本组顾客列表 |
| PUT | `/<uid>/points` | 调整积分 |
| PUT | `/<uid>/ban` | 禁用顾客 |
| PUT | `/<uid>/unban` | 解封顾客 |
| DELETE | `/<uid>` | 删除顾客（软删除） |

### 评论 `/v1/comments`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/dishes/<dishId>/comments` | 菜品评论 |
| POST | `/comments` | 发表评论 |

## 七、数据库表关系

```
user (管理员/顾客)
 ├── 1:N → order
 ├── 1:N → points_flow
 ├── 1:N → comment
 └── 1:N → exchange_request

order
 └── 1:N → order_item
              └── N:1 → dish

dish
 ├── N:1 → category
 └── N:N → user (通过 dish_visible_users)

exchange_reward
 └── 1:N → exchange_request
```

---

## 八、关键业务规则

1. **口令注册**：顾客注册时输入管理员的 `group_code`，自动归属该管理员
2. **积分不能为负**：所有扣积分操作会检查余额
3. **昵称每月改一次**：30 天冷却期
4. **订单号格式**：`ORD` + UUID 前 28 位
5. **JWT 有效期**：2 小时
6. **软删除**：菜品用 `is_deleted`，用户用 `deleted_at`
